**Effort**: high  
**Amended**: a hi-res file that is already `.flac` keeps its name (no second `.flac`), found by the red pass: a surviving mutation showed `media_path(converted=True)` would have named it `x.flac.flac`, which the route refuses (2026-11-03) — cited: src/sonos_cli/library.py media_path, criterion 1  

**Description**: A URL for a file that needs conversion ends in `.flac`: `/media/<root-id>/<relative path>.flac` (`hires.wav` becomes `hires.wav.flac`), so the original name is kept and can't collide with a real `hires.flac` beside it. The media route serves a path that exists as it always did; a path that doesn't exist and ends in `.flac` is looked up without that suffix and served only when that file needs conversion. URLs already queued under the old name still work as before (they convert and serve, though a speaker may refuse them). Nothing is stored: the name is a function of the file, so URLs stay stable across restarts.

### Limits

- The Music view's playing-row highlight (`markCurrent` in `app.js`) matched a row by the end of the URL and so never matched a converted file's `…wav.flac` (found by audit round 1; not covered by any criterion above): its pattern now accepts an optional `.flac`. Browser-observed at http://localhost:8761/ (`--fake-rooms`, scratch config with a generated 24-bit 96 kHz 20 s WAV): while the hi-res file played under `…/tone-hires-96k24-20s.wav.flac` the row `tone-hires-96k24-20s.wav` carried the `current` class and no other row did; a plain 60 s tone then highlighted only its own row. Control in node: for rel `/GLDR/hires.wav` and URL `…/GLDR/hires.wav.flac` the old pattern gives `false`, the new `true`, a plain `a.wav` still `true`, and `b.wav.flac` does not match `a.wav`.
- If a real file named `x.wav.flac` exists beside a hi-res `x.wav`, queueing `x.wav` builds the URL `…/x.wav.flac`, and a path that exists is served as itself, so the speaker plays the other file. Unusual; the alternative (refusing to serve a real file) would be worse.
- A converted track the speaker has not read tags for is labelled from the last part of its URL (`hires.wav.flac`); tracks with tags show their own title. The queue-label clean-up in `remote.queue_title` covers page tracks only.
