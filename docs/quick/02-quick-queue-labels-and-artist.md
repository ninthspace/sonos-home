**Description**: An S1 speaker reads a file's tags only for the track playing and the next one, and titles every other queued track from the last part of its URL (`Tideway.mp3`, no artist), whatever title the DIDL entry carried (found in 01-06 Story 3; read from the real Office on 2026-11-03). So the queue panel showed two kinds of label. This change makes the unread ones read like the tagged ones: the service takes the release artist from the Faircamp page, puts it in the proxy URL's name (`Tideway by SHTL.mp3`), and turns that name back into a label (`Tideway by SHTL`) when it builds the queue. Nothing is stored: the label travels in the URL, so it survives a service restart. Faircamp's `playlist.m3u` is not an alternative: it lists only Opus files, which S1 can't play.

### Limits

- Titles with non-ASCII characters were checked against the fake speaker only; on the real Office only a title with spaces (`%20`) has been seen. If an S1 returned such a title still percent-encoded, `queue_title` would leave it as the speaker gave it: safe, but unlabelled.
- The URL name carries the release's artist list, while a track the speaker has read shows that track's own tag artist, so on a various-artists release the two kinds of row can still differ.
- Every red pass ended with the mutated source files and the test files byte-identical to before (checksums compared after each run).

### Not changed

- The DIDL title and the Now playing line still use the speaker's tags when it has them.
- Epic 01-06 Story 3's Evidence (`Halyard.mp3` as the end of the proxy URL, queue titles `Halyard`/`Undertow`) describes the code before this change; it is amended there.
