**Source**: the user asked why Office, playing Foreshore track 3, reported an empty title (2026-11-03). Read from the real Office: `get_current_track_info()` gave `title: ''`, `artist: 'SHTL'`, `album: 'Foreshore'`, while its `metadata` DIDL holds `<dc:title>Tideway</dc:title>`. Cause: SoCo 0.32.1 `get_current_track_info` (`soco/core.py` `_title_in_uri`, about line 2150) discards a metadata title that also appears in the track URI, and our proxy URL's name (`…/Tideway%20by%20SHTL.mp3`, before that `…/Tideway.mp3`) always contains the title. Affects every page track since epic 01-06; the UI hid it by falling back to the queue label. Spec FR9 (the room's current track), AD8 (RoomMonitor state).  

**Description**: In the RoomMonitor's poll (`src/sonos_cli/rooms.py _poll_group`), when SoCo's title is empty, take `dc:title` from the track's metadata DIDL, unless the track is a radio-style stream (duration `0:00:00` or none) or that title is a URL. Nothing else in the state changes.

**Acceptance Criteria**:

- For a track whose SoCo title is empty and whose metadata has a `dc:title`, the room state's `track.title` is that title: with the real Office metadata captured on 2026-11-03 (Tideway, a `/remote/…/Tideway%20by%20SHTL.mp3` URI, duration `0:06:18`) the state reads `Tideway`, and the same holds for a local `/media/` file whose name contains its title. `[unit]`
  - Evidence: `tests/test_rooms.py::test_an_empty_soco_title_is_taken_from_the_metadata_for_page_tracks_and_local_files` (the real Office DIDL as the fixture, and a `/media/` variant) and `::test_the_metadata_title_reaches_the_room_state` (through `RoomMonitor.refresh_group_of` with the fake's track info replaced by the Office fixture) — red: `AssertionError: assert '' == 'Tideway'` with `rooms.py _poll_group`'s `track_title(track)` changed back to `track.get("title", "")` (second test), and the same message with `rooms.py track_title`'s `found = (found or "").strip()` changed to `found = ""` (first test)
- The fallback is not used, and the title stays as SoCo gave it, when: SoCo already has a title (it is kept, not replaced); the duration is `0:00:00` or empty (radio and live streams, where SoCo's own radio parsing decides); the metadata title is a URL (contains `://`) or is the track URI's last segment, decoded (a track with no title tag, e.g. `Halyard by SHTL.mp3` or `a b.flac`), where the UI's queue label is the better name; the metadata is empty, `NOT_IMPLEMENTED` or not valid XML (no error, the poll still succeeds).
